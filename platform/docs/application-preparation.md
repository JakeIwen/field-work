# Combined application preparation

Generate Docs coordinates form inspection, validated tailored PDFs, written answers and one immutable autofill script with embedded attachments. A considering Opening can move through preparing to ready without submitting anything. Interrupted service runs pause for explicit retry.

## Answers before documents

Shift-click uses `{scope: "answers"}` on the same queue: form, answers, packaging. It creates no Application, generates no PDFs and changes no stage. A later full preparation reuses current answers under posting/evidence/question guards, then finishes document work. Answers scope cannot combine with a document-kind replacement.

The live parallel-preparation setting bounds admitted runs; raising it wakes the queue and lowering it never interrupts admitted work. Duplicate requests deduplicate. Captured policy, evidence and writing rules remain bound to each task.

## Material controls and refresh

The Opening exposes Generate Docs until a usable full package exists. Answers-only scripts exclude generated resume/cover-letter uploads from their completion count but do not pretend those attachments exist. A full script without required PDFs remains incomplete.

Each PDF can be regenerated independently with a document-kind request. Exclusion lists prevent a retry from selecting the version it is replacing. Existing versions and the unaffected PDF remain intact. Reuse requires current posting/evidence and intact owned objects; app-code or helper-version changes alone do not expire them.

## Progress and live activity

Durable preparation phases include history. The activity endpoint combines the run, its tasks and in-memory agent signals only during active turns. The client polls visible busy Openings and pauses hidden tabs. Live liveness signals are not persisted as repeated task writes.

Client notices silently establish an initial baseline, then coalesce started, finished and stopped transitions by scope with current running/limit/queued counts. Multiple notices remain independently dismissible. Errors and stale output remain recoverable rather than being hidden by a progress label.

## Generated document retention

Publication prunes older generated PDFs beyond the retention window per Opening, kind and privacy. Active preparations, sent packages, current scripts and running work protect referenced bytes. Older scripts embedding pruned bytes and their references are removed together. Object ownership checks precede filesystem changes.

Deletion safety rechecks surviving records and status/phase guards before late completion. Deleted runs cannot be resurrected or marked ready. Missing dependencies fail explicitly, and scheduler failure handling contains errors.

## Writing-rule freshness

Canonical prose rules are fingerprinted separately from factual evidence and renderer inputs. A rule change marks only affected PDFs and attachment scripts out of date; unaffected documents and current answers remain reusable. A task can finish under its captured rules, with output flagged afterward. Historical bundles and artifacts are never rewritten.

Measured trusted-renderer overflow can request bounded shortening follow-ups. Repair turns retain source, request/turn ownership and cancellation guards. Unknown identities fail closed rather than hydrating a guessed task. Renderer layout is not changed to hide overflow.
